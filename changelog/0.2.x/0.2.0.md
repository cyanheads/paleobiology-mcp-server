# 0.2.0 — 2026-06-27

**Breaking:** the `paleobiology://taxon/{taxon_no}` resource now returns `first_appearance` and `last_appearance` at the top level — matching `paleobiology_get_taxon` — instead of nesting them under a `range` object. Clients reading `range.first_appearance` from the resource must read `first_appearance` directly.

## Fixed

- **`paleobiology://taxon/{taxon_no}`** — lifts `first_appearance`/`last_appearance` to the top level so the resource is a true mirror of `paleobiology_get_taxon`. Both surfaces now shape through one shared `shapeTaxon` helper and cannot drift. ([#1](https://github.com/cyanheads/paleobiology-mcp-server/issues/1))
- **`paleobiology_get_diversity`** — bins are ordered oldest-first (oldest interval, highest `max_ma`, first) in both `structuredContent.bins` and the `content[]` table. PBDB returns them newest-first, which contradicted the documented oldest-first order. ([#2](https://github.com/cyanheads/paleobiology-mcp-server/issues/2))
- **Required output fields** — `accepted_name` and `rank` on `paleobiology_get_taxon`, and `interval`/`max_ma`/`min_ma` on each `paleobiology_get_diversity` bin, are now required in their output schemas. The handler and normalizer throw `ServiceUnavailable` when PBDB omits any of them rather than emitting an incomplete record. ([#4](https://github.com/cyanheads/paleobiology-mcp-server/issues/4))
