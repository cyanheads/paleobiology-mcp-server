# 0.3.1 — 2026-07-30

## Added

- **`classification`** — occurrence rows now carry the higher classification (phylum → genus); `search_occurrences` and `dataframe_query` document it, and `dataframe_query` explains the `json_extract_string(classification, '$.family')` rollup pattern. ([#17](https://github.com/cyanheads/paleobiology-mcp-server/issues/17))
- **CC BY attribution** — `paleobiology_get_taxon` emits a CC BY 4.0 attribution enrichment; the occurrence and taxon resources carry the same credit as a plain payload field, since resources have no enrichment mechanism to ride. ([#21](https://github.com/cyanheads/paleobiology-mcp-server/issues/21))

## Changed

- **PBDB not-found reclassification narrowed** — only `taxa/single`'s HTTP 400 (an invalid scientific name) reclassifies as not-found; every other endpoint's 400 now surfaces as `InvalidParams` carrying PBDB's own rejection text instead of masquerading as "no match". Adopts the framework's `expectedStatuses` on `getOccurrence`/`getTaxon` so an ordinary single-record 404 logs at debug instead of error. ([#10](https://github.com/cyanheads/paleobiology-mcp-server/issues/10))
- **`dataframe_query` field guidance** — corrected which fields exist on a staged occurrence row (`early_interval`, `accepted_name`; no `lithology`, a collection-only field). ([#18](https://github.com/cyanheads/paleobiology-mcp-server/issues/18))

## Fixed

- **Bounding-box and Ma-range validation** — `search_occurrences`, `search_collections`, and `get_diversity` reject a half-specified `lngmin`/`lngmax` box (`incomplete_bbox`) and an inverted or equal `min_ma`/`max_ma` window (`inverted_ma_range`) at the tool boundary, before any PBDB request. ([#10](https://github.com/cyanheads/paleobiology-mcp-server/issues/10))
- **`canvas_id` gating** — `search_occurrences` returns `canvas_id` only when the result actually spilled to a canvas; an inline result no longer points at an empty table. ([#16](https://github.com/cyanheads/paleobiology-mcp-server/issues/16))
- **`list_intervals` sort order** — `IntervalIndex.filter()` returned raw snapshot order instead of the oldest-first order the schema promises; it now uses the same comparator as `all()`. ([#11](https://github.com/cyanheads/paleobiology-mcp-server/issues/11))
