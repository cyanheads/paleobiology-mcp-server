# 0.3.3 — 2026-07-30

## Added

- **`offset`** on `paleobiology_search_occurrences`, threaded to `occs/list` alongside `limit`. `records_found` is independent of `offset`, so the same true total anchors every page; notices name the exact page bounds and the offset that reaches the next one (`"Showing occurrences 1–500 of 4196. Advance offset to 500 for the next page."`), and a page requested past the end reports the overshoot instead of blaming the filters. The "raise limit" hint now only appears when `limit` — not the server-wide `PBDB_MAX_OCCURRENCES` cap — bounded the page and there is headroom below the 500 max. ([#14](https://github.com/cyanheads/paleobiology-mcp-server/issues/14))
- **`base_id`** on `paleobiology_search_occurrences`, `paleobiology_get_diversity`, and `paleobiology_search_collections` — the same clade-inclusive filter as `base_name`, keyed by the PBDB `taxon_no` (mapped upstream as `base_id=txn:<n>`) instead of a name. Supplying both is rejected locally with a typed `conflicting_taxon_filter` error rather than PBDB's own HTTP 400. `paleobiology_get_diversity`'s `base_name` is now optional, since exactly one of `base_name` / `base_id` is required — that tool also gained a `missing_filter` guard it previously lacked. `paleobiology_get_taxon`'s `taxon_no` output and description now point at `base_id` as its destination on the other three tools. ([#20](https://github.com/cyanheads/paleobiology-mcp-server/issues/20))
- **`children_offset`** input and **`children_offset`** / **`children_truncated`** output on `paleobiology_get_taxon`. The immediate-child pull over-fetches one row past the 200-row page (`TAXON_CHILDREN_PAGE_SIZE`) to detect truncation within the same upstream call, since PBDB's `taxa/list` reports `records_found` as `min(limit, true_total)` — always equal to the rows just returned — so it cannot disclose a clipped child list the way `occs/list` and `colls/list` can. `children_truncated: false` is an explicit "this page reaches the end," not an absent field. A page requested past the end of the child list reports the overshoot instead of reading as a childless taxon. Disclosure lands in both the `notice` enrichment and `format()`'s `content[]`. ([#15](https://github.com/cyanheads/paleobiology-mcp-server/issues/15))
