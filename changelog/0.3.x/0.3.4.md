# 0.3.4 — 2026-07-30

## Added

- **PBDB fallback** on `paleobiology_list_intervals` for a name absent from the bundled ICS snapshot — the sub-stage and regional names (`Late Maastrichtian`, `Lancian`) that `paleobiology_search_occurrences` and `paleobiology_search_collections` report in `early_interval`/`late_interval` but the offline snapshot does not carry. The fallback fires only when the name is missing from the snapshot entirely; a name the snapshot knows that a `level` or Ma filter excludes stays a bundled, no-network answer. ([#19](https://github.com/cyanheads/paleobiology-mcp-server/issues/19))
- **`source`** output field (`"bundled_ics"` | `"pbdb_upstream"`) naming which side answered, and **`scale`** on an interval resolved upstream — the PBDB time scale it belongs to (e.g. "Mesozoic Subages"), since every bundled interval is on the international scale.
- **`interval_lookup_unavailable`** error contract entry (`ServiceUnavailable`, retryable) for an unreachable PBDB during the fallback lookup, kept distinct from `interval_not_found` so an outage is never read as "that interval does not exist."
- `PbdbService.lookupInterval` and `normalizeInterval`, plus a `scale_no` → scale-name directory fetched once per process from `timescales/list` and cached.

## Changed

- `IntervalLevel`/`level` output widened to accept any PBDB rank string (`subage`, `subepoch`, `zone`, `subzone`, `chron`, `subchron`, `bin`) in addition to the five international-scale ranks, since an upstream-resolved interval can carry any of them.
- `paleobiology_list_intervals` annotation `openWorldHint` is now `true` — the tool can hit the network on a snapshot miss.
- `interval_not_found`'s recovery hint now points at browsing the international scale rather than claiming the whole time scale is bundled.

## Fixed

- `docs/design.md`'s references to the snapshot data file (`ics-time-scale.json` → the actual `time-scale-data.ts`), two `IntervalIndex` methods that no longer exist (`byMaRange`, `resolveInterval`), and the bundled interval count (200 → the actual 171) — all pre-existing drift from the current source.
- `README.md`, `CLAUDE.md`, and `AGENTS.md` no longer state that `paleobiology_list_intervals` never makes a network call.

## Dependencies

- `@types/node` `26.1.1` → `26.1.2`
