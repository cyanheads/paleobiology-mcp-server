# 0.3.2 — 2026-07-30

## Changed

- **`totalCount`** on `search_occurrences` and `search_collections` now reports the true upstream match count (PBDB's `records_found`, via `rowcount`), not the size of the staged/returned page — `shown` / `row_count` still carry the page size. Notices state the exact remainder (`"staged 500 of 4196 matching"`) instead of "more may match". ([#13](https://github.com/cyanheads/paleobiology-mcp-server/issues/13))
- **`search_collections` truncation** — now derived from `offset + shown < records_found` instead of `shown >= cap`, which falsely flagged a final page that happened to exactly fill `limit`. ([#13](https://github.com/cyanheads/paleobiology-mcp-server/issues/13))

## Fixed

- **PBDB `warnings[]` surfaced** — `parseEnvelope()` now carries `warnings[]` out alongside the parsed records instead of discarding them; `search_occurrences`, `search_collections`, and `get_diversity` compose them into their `notice` enrichment. Previously an unrecognized `lithology` value made PBDB silently return its full unfiltered result set with no indication the filter was ignored, and an unmatched taxon name was indistinguishable from a valid query with zero overlap. ([#12](https://github.com/cyanheads/paleobiology-mcp-server/issues/12))
- **`search_collections` offset past the end** — an empty page requested beyond `records_found` now reports that the offset overshot the match count, instead of telling the caller to widen filters that matched fine. ([#13](https://github.com/cyanheads/paleobiology-mcp-server/issues/13))
